# EVIDA의 연구 루프

EVIDA는 연구자의 질환·개발 목표를 받아 **어떤 기전을 겨냥하고, 어떤 후보를 비교하며, 다음에 무엇을 시험할지**를 하나의 연구 기록으로 연결합니다.

## 입력에서 다음 판단까지

1. **목표 구조화.** 자연어 요청을 연구 질문, 원하는 변화, 대상·조건, 필요한 산출물로 정리합니다. 원문과 연구자의 정정도 함께 남겨 구조화한 해석을 다시 확인할 수 있습니다.
2. **조사와 계산 계획.** 주 오케스트레이터는 현재 결정에 필요한 정보와 선택 이유를 적고, 등록된 문헌·웹·계산 도구를 호출합니다. 근거의 적용 조건에 따라 독립적으로 진행할 수 있는 갈래와 선행 정보가 필요한 갈래를 나눕니다.
3. **실제 자료 취득.** 공개 웹·Chrome 문서 열람, PubMed·Europe PMC, 질환·표적·임상시험·약물 라벨 API 등으로 자료를 얻습니다. 읽은 원문 위치, 자료 해시, 조회 실패와 미확인 범위를 보존합니다.
4. **후보와 계산.** 기전·개입 방향과 연결한 후보를 원출처와 함께 저장하고 필요한 물성·전하·구조·도킹·동역학·경로·RNA 계산을 실행합니다. 계산의 입력·단위·실행 조건과 원출력을 함께 남깁니다.
5. **가설과 구별 실험.** 같은 추론 코어가 근거와 계산을 종합해 조건부 가설, 비교할 대안, 일정하게 둘 조건, 읽을 값과 결과별 다음 행동을 구성합니다. 출처·대상·변수·예측의 참조는 코드가 검사합니다.
6. **결과 반영.** 연구자가 관측이나 조건을 저장하면 기존 판단을 보존하고, 별도의 재검토 요청으로 후속 판단을 실행합니다. 유지한 내용과 바뀐 이유를 같은 연구에서 확인합니다.

이미 치료제가 확인되는 경우에는 적용 대상·효과·위해·남은 한계를 조사하고, 연구자의 목표에 맞춰 개선할 지점과 다음 비교를 찾습니다. 도구 간 차이는 각 도구가 측정·예측한 양과 가정, 입력 조건을 바탕으로 해석합니다.

## 주 오케스트레이터와 추론 코어

주 오케스트레이터는 모델의 계획·도구 선택과 `Runner`의 실행·저장·검사 루프가 함께 구현합니다. `goal_supervision.py`가 다음 연구 결정, 필요한 정보, 진행 조건을 드러내고, `Runner`가 등록된 worker와 실제 외부 도구를 실행합니다. 작업 상태와 실제 응답 모델도 기록합니다.

공유 추론 코어는 500개 문헌 사례의 추출·분류 기록에서 만든 48개 조건부 원리를 검색해 활용합니다. 원리에는 적용 상황, 가설을 만드는 관점, 정보를 선택할 이유, 비교 설계와 결과 갱신, 원문 위치가 연결됩니다. 조사 선택부터 가설·실험·재검토까지 같은 원리를 참조합니다. 문헌에서 추출한 조건과 대안은 각 새 연구의 실제 근거에 대조합니다.

| 구현 | 책임 |
|---|---|
| `server.py`, `interaction.py`, `store.py` | 입력·revision·판단·관측·출처와 이력 |
| `runner.py`, `research_loop.py`, `goal_supervision.py` | 계획·도구 실행·진척 확인·후속 판단 |
| `reasoning_core.py`, `reasoning_perspectives.py` | 공유 원리 선택과 단계별 추론 입력 |
| `contracts.py`, `hypothesis_review.py`, `finalization.py` | 출력 구조·출처·가설과 실험 관계 검사 |
| `science.py`와 각 worker | 43종 계산·분석 함수 및 자료 조회 실행 |
| `web/` | 핵심 판단·분자 구조·단계별 상세·원결과 조회 |

원리의 구축 자료와 독립 검수 범위는 [추론 코어](REASONING_CORE.md), 도구 연결은 [계산 도구](COMPUTATION_TOOLS.md)에서 확인할 수 있습니다.

## 실행 경로

공개 서비스의 기본 모델은 대회 API GPT-6 Sol · medium입니다. HTTP 403 안내에서 방문자가 제출자 구독 경로를 직접 선택합니다. 각 실행은 요청·실제 모델, 호출·작업 상태를 기록합니다. 운영 런처와 검수한 자원 설정은 과학 worker에 같은 환경을 연결합니다. 인증·운영 DB·사용자 자료는 운영 서버에서 관리합니다. 소스 검토와 자체 설치 조건은 [런타임 안내](../runtime/README.md)를 참고하세요.
