# 제품 구조

**연구 목표 → 질문·기전·후보 구조화 → 공개 자료와 계산 → 다음 실험 → 새 관측에 따른 재검토**가 한 연구 기록 안에서 이어집니다.

| 계층 | 실제 구현 | 역할 |
|---|---|---|
| 연구 입력 | `server.py`, `interaction.py` | 질환·목표, 설명 질문, 조건 변경과 새 관측을 받음 |
| 연구 기록 | `store.py` | 연구별 revision·판단·발견 목록·원자료·작업 이력을 보존함 |
| 계획과 실행 | `runner.py`, `research_loop.py` | 모델이 선택한 도구를 실행하고 결과를 다음 판단에 전달함 |
| 근거 검사 | `contracts.py`, `evidence_bundle.py` 등 | 구조, 실제 출처·원행, 가설과 실험의 참조 관계를 검사함 |
| 과학 도구 | `science.py` 및 구성 모듈 | 고정 환경에서 구조·활성·생성·RNA 관련 계산을 수행함 |
| 사용자 화면 | `web/` | 연구 대화·작업물·상세를 연결하고 원자료와 판단을 왕복함 |

모델은 목표 해석·가설 비교·다음 행동 구성을 담당합니다. 코드와 도구는 실제 조회, 계산, 저장 및 참조의 일관성을 담당합니다. 과학적 해석은 출처가 적용되는 질환·모델·시험 조건과 함께 제시합니다.

공개 서비스의 모델 경로는 `evida/model_routes.py`가 연구마다 고릅니다. 기본은 대회 API(GPT-6 Sol · medium)입니다. 대회 API가 토큰 사용량 한도(HTTP 403)를 반환하면(`evida/gateway.py`가 분류) 방문자가 `runtime/`의 제출자 구독 경로(Claude Opus 5 · medium, GPT-6 Sol · medium)를 직접 고를 수 있으며, 다른 경로로 자동 전환하지 않습니다. 구독 경로도 같은 Runner에 연결됩니다. 고정 입력 색인, JSON 행동 봉투, 제품 계약 검증을 거치고, 요청한 모델과 실제 응답 모델이 같을 때만 결과를 씁니다. 경로마다 호출 한도와 동시 실행 한도를 둡니다.

연구자가 기전을 클릭하면 연결 후보와 근거를 봅니다. **이 기전 검토하기**를 누르면 선택 이유를 입력하고, 저장 또는 실제 재검토를 명시적으로 실행합니다. 전체 발견 목록과 추천을 함께 보존해 다른 경로도 이어갈 수 있습니다. 새 실험 결과가 들어오면 이전 판단과 후속 판단의 차이를 같은 기록에서 확인합니다.

코드의 도구 목록, 완료한 방법 시험, 운영에 채택한 범위는 [방법 안내](METHODS.md)에 정리했습니다. 이 소스에는 배포 자원 템플릿이 포함돼 있으며, 자체 운영 시 인증·외부 자원·과학 환경을 준비하고 검수합니다.
