# ReaSyn reaction-path trial on two EVIDA candidates

This experiment asks whether an [author ReaSyn v2 model](https://github.com/NVIDIA-BioNeMo/ReaSyn/tree/8a0b02178e90424266be424765b2e410dd10ab10) can return inspectable reaction paths for two EVIDA-generated candidate structures using only a public building-block catalog. The archived author runs returned **175 distinct product structures**. Independent replay confirmed the action sequence and final product for every row: **108 rows contain one or more reaction steps; 67 rows are public building blocks returned with zero reaction steps**. None of the outputs exactly equals its *parsed* input target. These are computational paths and structural analogs, not evidence of successful laboratory synthesis or biological activity.

| Input | Archived result | Products | Verified reaction paths | Stock-only results | ReaSyn similarity, median (range) |
|---|---|---:|---:|---:|---:|
| proposed-2 | [run 01](results/run-01-proposed-2.csv) | 75 | 31 | 44 | 0.245 (0.048–0.642) |
| proposed-1 | [run 02](results/run-02-proposed-1.csv) | 100 | 77 | 23 | 0.243 (0.087–0.493) |

The two input structures and their earlier EVIDA GP **predictions** are in [candidates.csv](inputs/candidates.csv). Their source-linked parent structures are two rows of [MoleculeACE `CHEMBL1862_Ki`](https://github.com/molML/MoleculeACE/blob/7e6de0bd2968c56589c580f2a397f01c531ede26/MoleculeACE/Data/benchmark_data/CHEMBL1862_Ki.csv), preserved in [parent-moleculeace-rows.csv](inputs/parent-moleculeace-rows.csv). Those parent Ki values are reported dataset aggregates. They are not measurements of the two proposed candidates or of ReaSyn products.

ReaSyn used the [official AR and EB v2 checkpoints](https://huggingface.co/nvidia/NV-ReaSyn-AR-166M-v2), the author's public [ZINC250k building blocks](https://github.com/NVIDIA-BioNeMo/ReaSyn/blob/reasyn_v2/data/building_blocks/building_blocks_zinc250k.txt) (37,386 structures), and the [115 ordered SynFormer reaction templates](https://github.com/wenhao-gao/synformer/blob/bef02bc4481adf3ed792090fc6169331d4d0553a/data/rxn_templates/comprehensive.txt). The ZINC-only fingerprint index and reactant–reaction matrix were computed from those public files; Enamine's catalog or preprocessed index was not used. The fixed author settings were one visible GPU and worker, one refinement cycle, search width 4, exhaustiveness 8, 300-second per-input limit, 100 edit-flow samples and 100 edit-flow steps. The two runs used the same weights, stock, templates and settings. [Source and weight hashes](MANIFEST.json) identify the exact materials.

Run 01 received a headerless `.smi` file. The author's RDKit supplier treated its first line as a header, so **only proposed-2** was actually modeled. Run 02 used a CSV with an explicit `smiles` header and modeled **only the missing proposed-1**. The original proposed-1 carries `@` stereochemical marks, but the author parser's `Molecule.csmiles` removes them before model input. Thus run 02 targets the parsed, stereo-unspecified structure; its outputs must not be described as paths optimized for the original specified stereoisomer. The raw CSVs are byte copies of the completed runs. Header correction did not regenerate or rescore run 01.

The independent [route summaries](verification/route-summary.json) and [all 175 replay records](verification/run-01-replay.jsonl) check each building-block token against the public stock **as an exact SMILES string**, map each `R` number to its template in the original order, apply the author's `Stack` operations, and require the reported output's canonical isomeric SMILES to be in the final product set. The second run's replay records are [here](verification/run-02-replay.jsonl). Every row passed those checks; `num_steps` matched the reaction-token count. For example, proposed-2's first returned path combines two stock inputs with `R49` to yield `O=C(Nc1nnc(SCc2ccc(F)c(F)c2)s1)c1ccc(F)c(F)c1`. Proposed-1's first returned path uses two stock inputs and `R43` to yield `Cc1ccc2ncc(C#N)c(NC3CCCCCC3c3ccccc3)c2c1`. The replay checks chemical graph/template consistency, not reaction conditions, yield, catalog availability, or assay behavior.

[Activity predictions for all 175 products and the original eight CReM candidates](results/activity-predictions.csv) are a **separate CPU calculation** with the same existing EVIDA `CHEMBL1862_Ki` Tanimoto GP scoring path. All 183 rows received new predictions in one fit and one score call; the original eight rounded scores matched their earlier values. The GP was selected using 475 training rows and a 158-row inner scaffold validation set. That validation Spearman (0.733) is for model selection, not independent validation of these new products. [The scoring summary](verification/activity-scoring-summary.json) preserves group sizes and prediction ranges. No parent prediction or measured Ki was transferred to a ReaSyn product. A larger predicted pKi or ReaSyn structural similarity does not establish greater potency, generator superiority, or a treatment recommendation.

To repeat the public-source workflow, use Python 3.12, Git, network access, at least 5 GB for the official checkpoints plus working space for the environment/caches, and a CUDA GPU compatible with PyTorch 2.7.1. The script checks official source SHA256 values, creates an isolated environment, preprocesses the public stock with at most two CPU workers, writes **headered** one-molecule CSVs, calls the unmodified author CLI once per input, and replays its new results. Choose the GPU explicitly after checking local availability. Only its local archive check was run while assembling this package; download, environment creation and GPU phases were not. Archived outputs are supplied above and may differ from a new stochastic run.

```bash
python3 reproduce.py archive
python3 reproduce.py prepare --work ./local-reproduction
python3 reproduce.py infer --work ./local-reproduction --gpu 0
python3 reproduce.py verify --work ./local-reproduction
```

The package contains the two original output CSVs, all-row replay records, public input and parent-source rows, the separate GP prediction table, summaries, source pins and license notices. It does not bundle checkpoints or preprocessed indexes. [NOTICE.md](NOTICE.md) identifies upstream licenses and data terms. This trial tests an inspectable reaction-path candidate-generation step; it does not compare ReaSyn against CReM under a matched generation budget or against LAVA.
