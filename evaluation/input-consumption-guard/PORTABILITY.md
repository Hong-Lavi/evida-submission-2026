# Code identity and reproduction boundaries

The original recording and portable reproduction are separate, retained experiments. Both exercise the same five event schedules with the same expected outcomes. The portable reproduction is not substituted for the original recording.

Most files in `native/` are exact byte copies of the original native dependency files. `source-map.json` records the original logical source name, original SHA256 and public SHA256 for every copied source and observation. The complete source fingerprints used for the original recording remain in `recorded-run/plan.json`; only workstation locations are replaced with logical identifiers.

The public `Runner` class contains exact source-line extracts of `frame` and `model_context` from each original implementation. Their AST bodies match the original functions, as verified while packaging and retained as hashes in the source map. The portable driver supplies the Store and the original `context_recent_views=2` setting. These are the attributes used by those methods in the frozen scenarios. It does not invoke the full Runner constructor, which checks scientific package/weight identities unrelated to these state transitions. Model/tool dispatch methods are not included in the extracted class.

The ordinary native Store, finalization, intent-consumption, intent-record and schema code is used directly. There is no replacement implementation of the stale-input check or transaction logic. A comment in each `discovery.py` copy clarifies when an assessment is processed; executable AST is identical. The optional NLI inference module is excluded because none of these fixed scenarios calls it, and it contains a deployment-specific interpreter locator. Other dependency modules are included to preserve native imports and schemas, but the driver executes only the supplied synthetic state paths.

Portable driver changes are limited to package-relative product locations, the stated offline Runner bootstrap, omitted unused pool shutdown, and loaded-module identity recording. The source fixtures, substantive decision bundles, five scenarios, native method calls, failure handling and outcome assertions are retained. Each implementation runs in a separate Python child process; an imported native module outside its frozen implementation directory is rejected.

The original synthetic proposals and before/after state JSON are retained unchanged, as are the property failures. Random workspace/artifact IDs and timestamps differ between independent executions. Verification compares scenario identity, expected and actual publication, assertion results and status, not those incidental IDs or execution time. Equality between implementations is checked separately within each run after mapping artifact IDs to source hashes.

All five scenarios are chosen examples with deterministic expectations. Their counts do not support population confidence intervals or a general agent-performance percentage. Scripted consumption metadata also does not measure whether a language model would declare correct provenance. No source-paper interpretation, effect-direction classifier, clinical outcome or biochemical computation is executed.
