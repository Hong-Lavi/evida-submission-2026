## Finding: P2 — truncated worker output aborts the full denominator

**Location:** `acquisition-01/run_selection.py:67–70`, together with non-atomic JSON writes in `common.py:18–21` and the explicitly allowed worker termination path in `selection_worker.py:65–66`.

The runner records an unsuccessful worker exit or timeout, then parses each existing baseline/posterior JSON file without guarding parse errors. CPU/wall/memory termination can leave a file present but incomplete while `json.dump` is writing. `load` then raises `JSONDecodeError` before `complete_rows` can fill failed rows, before the task receipt, and before later tasks run. This contradicts the frozen design's full task/method denominator under worker failure. It fails closed with respect to gold, so this is an execution-accounting problem rather than demonstrated label leakage.

Independent reproduction replaces the subprocess with a synthetic worker that writes `[{"task":` to its own temporary `baseline.json` and exits -9. Of two planned synthetic tasks, only one launches; the runner raises `JSONDecodeError`; zero terminal receipts and no selection seal are written. The reproduction imports the real runner and does not change it. The temporary fixture is removed after recording the result.

**Minimal repair:** preserve the partial bytes, classify the unreadable worker artifact explicitly, retain valid rows from other intact artifacts, fill missing rows as failures with the declared separate GP fallback where applicable, and continue remaining tasks without retry. An atomic worker-save operation reduces the partial-write exposure, but the parent should still handle invalid/missing worker artifacts because killed workers are explicitly in scope. Regenerate the unfrozen draft's source pins after any repair. Preserve the original reproduction rather than rewriting it as a passing test.

## Reviewed numerical and statistical behavior

- **Denominator:** the draft declares 30 tasks, 29 target clusters, 9,802 candidate rows, 8 methods × 3 batches × 5 seeds = 3,600 selection rows. This metadata was inspected without reading candidate values. `prepare_protocol.py:79–81` verifies the source task totals and the retained GP25/RF5 choice; `selection_worker.py:40–41` applies that saved choice, with no new model selection.
- **qPO:** `acquisition.py:89–102` counts uncovered winner-set events. Unique winners reduce to additive fixed-b coverage; independent exhaustive subset comparison agrees. With nonunique maxima it matches an independent greedy union-coverage oracle. It is correctly described as greedy S1 coverage, not a globally optimal batch guarantee. Once every sampled event is covered, zero-gain additions use GP mean/ID deterministically; that does not create extra coverage.
- **pTop10:** `acquisition.py:75–86,125–127` allocates residual boundary slots uniformly across exact ties and ranks expected membership. Exhaustive random tie-order enumeration agrees. This maximizes the empirical fractional-membership additive utility, while the prespecified primary measured metric uses ID-resolved top10. Those utilities differ at exact ties; the draft discloses the fixed primary and fractional sensitivity, so do not describe pTop10 as an exact optimizer of the ID-resolved measured metric.
- **Latent versus observation:** `acquisition.py:109–129` uses the same latent draws for both acquisitions, and a separate independent stream for saved likelihood variance (`observation_sd² − latent diagonal`). A synthetic all-equal latent pool with 8,192 draws stays exactly tied in every latent draw; nonzero observation noise removes exact observed ties. No diagonal jitter is added. Equality tolerances, spectral projection, and maximum corrections are exposed in diagnostics; these are numerical approximations, not biological equivalence claims.
- **Seeds:** five seeds represent Monte Carlo/random-selection variation, not independent biological tasks. Aggregation first averages within each task and requires all seeds for raw paired analysis (`score_selection.py:120–146`). Full-denominator operational zero-hit metrics are separately named; a failed selection is not silently scored as a measured negative activity.
- **Failure/fallback:** `run_selection.py:21–41` retains explicit missing rows and separates GP fallback IDs from original selections, provided the parent reaches this function. `score_selection.py:111–116,129–142` preserves raw, fallback-policy, and operational modes. Raw comparisons can use fewer tasks; results must retain their reported denominators. The finding above is the uncovered path preventing this design from completing.
- **Cluster confidence intervals:** `score_selection.py:155–174` resamples whole target clusters, then divides summed paired differences by the resampled task count. This targets equal-task macro differences while keeping both CHEMBL237 endpoints together. An independent flattened-cluster bootstrap oracle matches point estimate and interval. Clusters are derived from the task prefix rather than the metadata field; the draft's current identifiers use the same definition. Intervals are exploratory marginal intervals, not multiplicity-adjusted or confirmatory evidence, and do not remove historical-label exposure.
