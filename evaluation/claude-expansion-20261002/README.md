# Claude 추가 E2E 평가 — 종료 기록

사전 지정한 **4질환 × 2지시 방식 = 8개 연구 단위에서 새 최종 E2E 완료는 0건**이다.
전송 형식을 수리하며 수행한 4건은 같은 질문의 수동 후속 시도다. 이를 새 독립 표본이나
기존 GPT 평가의 성공으로 합산하지 않는다. 최종 답변이 없으므로 최종 과학 정확도는
평가 불가이며, 정확도 0%나 100%를 부여하지 않는다.

| 전송 조건 | 대상과 상태 | 실제 실행 시도 | 영구 예약 / 실제 전송 | native 응답 / 적용된 연구 프레임 | 공개 조회 | 최종 게시 |
|---|---|---:|---:|---:|---:|---:|
| 01: 본문 JSON 문자열 | 류마티스 관절염·파킨슨병 시작, CF·PDAC 4건 미시작 | 4 | 5 / 5 | 2 / 2 | 0 | 0 |
| 02: 최상위 typed union | 미시작 CF·PDAC 4건; 공급자 schema HTTP400 | 4 | 4 / 4 | 0 / 0 | 0 | 0 |
| 03: 객체 안의 typed response | 같은 CF·PDAC 4건의 수동 호환 수리 | 4 | 8 / 7 | 7 / 4 | 2묶음·8건 | 0 |

CF는 낭성섬유증, PDAC는 췌관선암이다. 연구 프레임은 연구 질문과 **제안 가설**을 기록한
단계이며 검증된 기전이나 완성된 후보·실험 권고가 아니다. 03의 공개 조회는 일반 조력자
A의 CF 연구 한 건에서 수행했다. 8건은 논리적 자료 조회 건수이며 HTTP 요청 수나 실험 수가 아니다.

총 12실행 시도는 원래 8연구 단위에 속한다. 실행기 내부 요청은 21건, 영구 예약은 17건,
실제 외부 전송은 16건이다. 4건은 공유 보류로 예약 전에 차단됐고, 1건은 예약 후 입력
검토에서 전송 전에 차단됐다. 원48회 승인 범위·운영 원장·이전 실패·보류는 보존했다.

모든 전송은 같은 기존 Claude 구독의 `claude-opus-5`, CLI `--effort high`로 요청했다.
실제 반환에서 Opus5를 확인한 요청은 12건이다. 02의 네 오류 응답은 모델 추론 전
거절이며 실제 과학 응답 모델로 집계하지 않았다. 형식·참조 검사를 통과한 응답과
공급자가 반환했다는 사실을 별도로 기록했다.

각 연구의 상한은 **일반 응답 5회(프레이밍·종합 포함) + 형식 보정 1회**, 새 작업 진입
35분, 외부 요청 1회 최대600초였다. 평가 전용 4동시 실행과 14:05 KST 종료 조건을
사용했다. 공급자 CLI 내부 메시지·Read 동작은 외부 응답 회수와 다르다. CLI의 별도
`--max-turns`는 지정하지 않았으며 실제 내부 동작 카운터를 함께 공개한다.

A는 일반 연구 조력자 지시, B는 현재 EVIDA planner 지시다. 같은 질환 질문·새 저장소·
도구·시간 상한을 사용했고 제품 파일의 두 arm 차이는 `configs/planner.md`뿐이다.
표적·후보·답안·이전 결과를 사전 제공하지 않았다. 도킹 및 점수 함수 변경은 하지 않았다.
자세한 조건은 [protocol.json](protocol.json), 사전 동결 기준은 [rubric.json](rubric.json)에 있다.

실제 수리·남은 결함은 다음과 같다.

- 01은 JSON 문자열 내부 문법 두 건과 허용되지 않은 도구 인수 한 건이 실패했다.
  이후 공유 보류 때문에 다른 연구의 후속 요청과 미시작 네 연구가 차단됐다.
- 02는 native 계약을 객체로 전달했지만 공급자가 최상위 `anyOf`를 HTTP400으로 거절했다.
  오프라인 schema 검사 통과가 실제 공급자 호환성을 보장하지 않음을 확인했다.
- 03의 한 단계 감싼 객체는 실제 공급자가 받아 native 응답 7건을 반환했다. 한 frame은
  탐색용 표식을 실제 근거 ID로 연결해 거부됐고, 다음 일반 응답에서 미확인 가설로
  보존하며 참조를 바로잡았다. 이후 CF-B의 필수 입력이 280,478바이트로
  196,608바이트 한도를 넘어 전송 전에 차단됐고, 나머지 세 연구도 공유 보류로 멈췄다.
- 같은 논리 입력의 작은 envelope 기준은 157,394바이트였다. 정확한 typed schema가
  123,084바이트를 더했다. 주석 제거·재인수분해의 오프라인 최대 절감 16,297바이트로도
  한도에 맞지 않았다. 추가 실행이나 한도 완화는 하지 않았다. 다음 수리는 전체 계약의
  전달 방식을 재설계하고 원문·작업 상태·참조·검증 규칙을 보존하는 것이다.

중간 과학 내용은 최종 성능과 따로 검수했다. A의 CF 메모는 환자 유래 세포 실험과
환자 투여를 구분했고, 일부 검색 행·초록의 조건을 정확히 유지했다. 반면 K+채널 관련
리뷰 초록에서 **CFTR 비의존성까지 확인됐다고 해석한 확장**은 해당 초록으로 뒷받침되지
않았다. [선택 원문 검수](partial-source-audit.json)는 이 한계를 그대로 남긴다.
뒤에 조회한 원 라벨·시험 결과는 다음 모델 종합에 사용되지 않았다. 완성된 구조·서열
후보 풀이나 여섯 요소의 최종 실험 카드는 없다.

| 원 보고 사용량 | 01 | 02 | 03 | 합계 |
|---|---:|---:|---:|---:|
| 새 input tokens | 66 | 0 | 88 | 154 |
| cache creation input tokens | 182,990 | 0 | 360,674 | 543,664 |
| cache read input tokens | 665,138 | 0 | 1,638,150 | 2,303,288 |
| output tokens | 78,364 | 0 | 121,972 | 200,336 |
| CLI Read 요청 | 67 | 0 | 79 | 146 |

최종 `reported_usage` 상위 카운터를 각 요청당 한 번 합산했다. 부분 카운터·모델별
중복 카운터를 더하지 않았으며 금전 비용이나 대회 크레딧 차감을 추정하지 않는다.
02의 토큰0은 실제 오류 반환의 보고값이다. 미전송 1건의 사용량은 적용 불가(`null`)다.
내부 response ID81에는 공급자 오류 기록4개가 포함된다. 요청 내부의 동일 Read
인수 반복 카운터는0이며, 서로 다른 호출 사이의 문맥 재전달이 없었다는 뜻은 아니다.

각 조건의 실제 dispatch 경과는 355.720초 / 13.646초 / 574.836초다. 조건별 실행 구간
합은 944.202초이고, 최초 시작부터 마지막 종료까지는 오프라인 수리·검수 간격을 포함해
2,699.367초다. 병렬 요청의 소요시간 합 3,030.913초는 실제 벽시계 경과와 다르다.
속도 향상이나 전송 형식의 과학적 인과 효과를 추정하지 않는다.

원래 8개 단위의 미시작·실패와 수동 시도는 [episodes.csv](episodes.csv), 모든 예약은
[provider-calls.csv](provider-calls.csv)에 있다. [summary.json](summary.json)과
[source-pins.json](source-pins.json)의 수치·무결성을 다음 명령으로 재계산할 수 있다.

```bash
python verify_report.py
```

공개 묶음은 메타데이터·검수 기준·해시·선택 검수 결론만 포함한다. 원응답·연구 DB·
인증정보·숨은 추론은 포함하지 않는다. 해시는 비공개 원기록의 보존 참조이며 원문 없이
독립 과학 재현을 제공하지는 않는다. 평가자는 준비에도 참여했으므로 완전 맹검이나
외부 독립 검증으로 표현하지 않는다. 기존 GPT16 및 별도 부품 벤치마크 결과와 합산하지 않는다.
