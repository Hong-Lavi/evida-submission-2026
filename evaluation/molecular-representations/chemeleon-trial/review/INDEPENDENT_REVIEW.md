# Independent pre-score review

Read-only inspection of the original frozen protocol, encoder, training and scoring code. No actual prediction values, official test gold or final scores were read. No model/network/GPU call or training interruption. Original files remain unchanged. The separately authorized gate below is implemented and synthetically tested, but has not been executed on the active run.

**Finding: pre-score verification order needed strengthening.** Original `score_comparison.py:42–59` validates follow-up prediction hashes before scoring, but verifies previous GP/RF fallback pins inside the task-scoring loop. The first task's gold can therefore be accessed before a later fallback pin is checked. It also does not compare the 30 seal entries to individual terminal receipts, or explicitly require a completed entry to have a non-null prediction hash. This is weaker than the protocol's “all source and prediction pins and all 30 terminal receipts before opening labels.” A source-extracted synthetic execution reproduced the ordering issue without accessing actual run files: see [synthetic-review-result.json](synthetic-review-result.json).

**Separate frozen amendment.** [prescore_gate.py](prescore_gate.py) verifies original protocol/source/weight pins and all 30 terminal receipts against the seal. It checks every completed and preserved partial prediction hash, all 30 prior GP/RF prediction pins, and all training/feature pins before parsing prediction JSON. Its second phase checks task identity, feature membership, unique candidate IDs, finite predictions, exact copied baseline rows/training metadata, encoder artifact hashes, and the already-declared inner-selection policy. All manifest bytes are rechecked before success. No gold path is opened by the gate. With `--score`, it writes a separate gate receipt then invokes the unchanged original scorer. Failed tasks keep their original technical-failure fallback and raw partial artifacts; no repair/retraining/reselection is introduced.

The [amendment](scoring-amendment.json) and [freeze receipt](scoring-amendment-receipt.json) were created before any follow-up gold read, per the root's explicit authorization and access declaration. The amendment pins the new gate and tests, plus the original protocol/scorer. It records the already-disclosed prior RF/GP outcome exposure. Do not run the original scorer directly for this follow-up; after all 30 tasks finish, run from the trial directory:

```sh
LD_LIBRARY_PATH=<user-home>/anaconda3/lib ../gp-env/bin/python -B review/prescore_gate.py --score
```

**Comparison validity from code inspection.** `run_comparison.py:57–80` captures the actual native RF training matrix/labels, matches their frozen prior hashes and reproduces native outer-test predictions. The frozen native `activity_model.py:139–154` returns the same ordered training rows used for that matrix. CheMeleon matrices are indexed in that row order, and both representations use RF 300 trees/minimum leaf 2/the same seed and installed defaults (`run_comparison.py:85–103`). The author fingerprint is reused with evaluation mode/no gradients; batching does not train on held-out or test labels. The stored author preflight reports batch invariance within tolerance. Encoding unlabeled test SMILES with fixed weights is not task-specific fitting. Pretraining molecule overlap was not audited, so this is not evidence of wholly unseen molecular structures during author pretraining.

**Metrics, policy and denominators.** Primary paired task-macro MAE difference, secondary RMSE/Spearman/top-10 tie-breaking and best selected activity match the frozen specification. Cluster resampling groups tasks by target; the mean remains task-macro, with explicit paired task and target counts. Synthetic tie-breaking and task/group-count checks passed. RF/GP inner MAEs are full-precision values preserved in the prior fit, not rounded display values. Spearman usability rounding is consistent across all three frozen arms. The three-way policy uses only inner assessments with RF→GP→CheMeleon tie priority. A failed CheMeleon task uses the previously chosen RF/GP policy, exactly as prespecified. `planned_tasks`, `baseline_tasks`, `completed_pairs`, per-arm macro denominators, failure receipts and policy-selection counts retain the full attempted denominator. If completion is below 30, the primary paired result is a complete-pair estimate, not an all-task performance estimate; failure coverage must accompany it. Policy comparisons likewise use only tasks where both policies emit a prediction, with their own paired denominator.

**Validation and limits.** Eleven new synthetic gate tests passed in 0.570 s. They prove that changed source, missing/mismatched last receipt, null completed hash, corrupt last prior pin, late nonfinite value, duplicate/foreign candidate ID and inconsistent stored policy prevent the first scoring/label callback. A passing 30-task fixture reaches that callback; a failed task retains its partial hash and frozen fallback. An initial review-helper fixture omitted its extracted function's `sys` global; the helper was corrected and the synthetic source-order check then passed. No production defect was masked by that fixture correction. Dependency versions are recorded in the original preflight, while source/weight hashes and native prediction reproduction constrain this run; this is not a fully hermetic environment build.

The coordinator already saw RF/GP outcomes on these same 30 tasks, explicitly disclosed at protocol freeze. Any successful CheMeleon result is a prespecified follow-up on reused tasks, not an independent fresh validation. No performance result is asserted by this review.
