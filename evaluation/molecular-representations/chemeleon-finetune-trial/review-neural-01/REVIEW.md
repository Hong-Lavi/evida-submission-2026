# Independent neural follow-up review — before outcome access

Reviewed frozen protocol `338a1e229ab3a848058eb694075159b8802ad3b873beb4949847a773932825ab`, its source files, earlier review code/handoff, and baseline code. No partial neural predictions, official-test gold or actual scores were opened for this design review. No training, model inference, network or GPU was performed. This review does not modify the trial or authorize public release.

**No new training-design blocker found.** The matched random-init control is appropriate for isolating the contribution of pretrained initialization within this architecture/training recipe. It is not a comparison of globally optimized architectures or compute-matched model families. The benchmark was already inspected historically, the protocol acknowledges that, and one seed cannot establish training-seed robustness.

## Calculation and comparison

- `prepare_data.py` reconstructs the recorded native largest-scaffold inner split and checks the exact training matrix/label digests against prior RF/GP. Labels enter only inner train/validation; official prediction payloads retain ID and SMILES. Earlier independent partition review reported all 30 exact checks passing; this review has read its method/handoff, not independently rerun those data checks yet.
- `finetune_adapter.py` fits normalization on training labels only; validation loss selects the best checkpoint with patience 5, then unscaled validation MAE/Spearman determines policy eligibility. Both neural arms construct the same architecture and initial head from the same seed, and retain singleton tail rows. Different selected epoch counts are allowed; report cost rather than claiming matched compute.
- `score_comparison.py` uses only stored validation results for eligibility and selection: rounded Spearman >= .3, MAE below training-mean MAE; GP additionally inherits optimizer convergence from its frozen usable flag. Lowest unrounded validation MAE wins, with RF/GP/pretrained/random tie order. Gold is available later in the same scoring loop, but the selection expression never reads it. There is no outer-label selector tuning in the code. Historical benchmark reuse still limits the external-validation claim.
- MAE/RMSE operate in p-activity units; ranking uses descending p-activity, with stable candidate-ID ties. Spearman average ranks ties and assigns 0 to constants, matching the recorded baseline convention. Top10 recall retains the original ID-resolved gold tie metric; do not silently replace it with fractional ties after viewing results.
- `metrics_common.cluster_interval` resamples target clusters and retains both CHEMBL237 endpoint tasks together. Within each resample it computes the mean across sampled task differences, matching task-macro rather than molecule-weighted performance. The effective denominator is 29 targets/30 endpoints when complete. Its percentile interval measures between-target sampling variation under this task set, not seed uncertainty, fresh-target validation or uncertainty in assay labels. Secondary metrics/comparisons are descriptive, not multiple independently confirmed findings. Negative MAE/RMSE differences favor the left arm; positive ranking metric differences favor it.
- Failures remain in the 60-arm ledger; reported numeric macro/paired comparisons use available completed tasks with explicit coverage. This is a success-conditioned performance estimate, not an all-planned accuracy score. A validation policy can retain a baseline even when a neural fit fails; disclose that coverage alongside model-only metrics. No mean predictor outer-test metric is supplied; the mean is an eligibility baseline only.

## Seal gaps and bounded independent gate

The unchanged scorer verifies protocol/source/weights/input/reference hashes, ordered 60 completion entries, completed prediction hashes, candidate order, finite predictions, validation MAE/Spearman and paired initial heads before its first gold access. Its new-file-only seal prevents silently overwriting an earlier seal.

Two gaps warrant an **additional check, not retraining or amendment of scientific choices**:

1. Every status other than `completed` is treated as failure without a terminal-status whitelist, and the completion rows are not compared with individual per-arm receipts. A malformed running/unknown entry could therefore count as terminal.
2. The scorer checks eligibility using the worker's stored `mean_validation_mae`, without recomputing that training-only mean baseline. The worker calculation is correct; this is an independent integrity gap rather than evidence of a wrong result.

`pre_score_gate.py` addresses these and verifies model identity/fit metadata. It first validates all 60 terminal entries **before any raw predictions or individual receipts**. It then checks receipt equality, frozen pins, complete unique ordered IDs, finite predictions, independent SciPy validation Spearman, MAE, training-mean MAE, eligibility, fit equality, task/arm/seed/version/device, checkpoint hashes and paired initial head hashes. Pinned author weights are deserialized weights-only on CPU solely to hash the original encoder tensors; no model is constructed. Initial pretrained encoder hashes must equal that source; random-init hashes must differ. All test-gold open attempts are blocked by an audit hook. It never invokes the scorer, changes predictions or retries training. A FAIL is preserved and stops the path.

The gate also rechecks all prediction/receipt and frozen input/reference/source hashes before PASS. Its output is a supplemental review seal, not a substitute for the original scorer's seal. Root executes the unchanged scorer only after PASS. Root then authorizes actual score access for independent recalculation.

Synthetic tests: **14 PASS**, including the last planned entry missing/running/unknown/no hash, skipped entries improperly carrying output, all-skipped 60 denominator, false mean baseline, false eligibility, constant predictions, tied ranks and clustered two-endpoint resampling. The first test draft had five failures only because its expected metadata-load order was reversed; the implementation already blocked artifact access, and correcting the fixture order resolved them. Logs retain the subsequent 11-test and 14-test passes. These unit tests do not establish that the real 60-artifact gate passes.

## Deployment and public-package boundary

This remains a trial, not a new deployed prediction tool. A reported gain would support the tested fixed assay endpoints and splits, not drug efficacy, calibrated uncertainty or general mechanism validity. Pretraining/evaluation compound overlap has not been ruled out; do not claim structurally unseen pretraining inputs. Retain contextual limitations of standardized assay labels and the reused benchmark.

For a later public package, use an explicit allowlist: own adapter/scorer/reproduction code, source URLs/commit/license attribution, protocol with machine-local paths removed, non-sensitive aggregate and per-task metrics, denominator/failure ledger, hashes, and independently checked result tables. Review MoleculeACE/data redistribution terms before including structures or labels. Author MIT licensing does not by itself establish rights for all downloaded datasets or article text. Do not copy the environment, credentials, local absolute paths, full run logs, training rows, best checkpoints or source weight files by directory recursion. Provide original weight acquisition/checksum instructions and a weights-only load path; do not encourage loading arbitrary public Lightning pickles with `weights_only=False`. The current adapter loads that format only for its own newly generated checkpoint.

No proposed public package was inspected in this phase. Package contents, full outcome recalculation and any adoption claim remain pending root's complete-run seal/score notice.
