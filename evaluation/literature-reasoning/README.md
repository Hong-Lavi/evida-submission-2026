# 문헌 질문에서 답변 정확도와 완료율 비교

같은 모델에 문헌을 제공하거나 문헌 도구를 연결했을 때, 정답과 실제 완료 수가 어떻게 달라지는지 비교했습니다. GPT-6.1 Sol · medium을 사용했고, 공통 코어의 48개 조건부 원리와 평가 조건을 실행 전에 고정했습니다.

## 원문을 제공한 15문항

LitQA2의 고정 문항 중 원문 XML을 확보한 15문항에 같은 전체 본문을 제공했습니다. 네 방식 모두 계획 15문항 중 정답 14건을 기록했습니다.

| 방식 | 계획 문항 | 채점 답안 | 정답 | 미채점·미실행 |
|---|---:|---:|---:|---:|
| 같은 LLM만 | 15 | 14 | 14 | 1 |
| 공통 코어 없음 | 15 | 14 | 14 | 1 |
| 공통 코어 있음 | 15 | 14 | 14 | 1 |
| PaperQA2 | 15 | 14 | 14 | 1 |

같은 LLM만의 1건은 HTTP 오류로 미채점이며, 다른 세 방식의 1건씩은 원입력 검사에서 호출 전 중단됐습니다. 채점한 같은 14대상의 CLI 실행 수는 앞의 세 방식이 각각 14회, PaperQA2가 144회였습니다. 자원 표는 구독 CLI 프로세스 실행 수를 기록합니다. backend RPC 수와 토큰 사용량은 미측정 값으로 남겼습니다.

PaperQA2는 공식 `v2026.08.12`의 Docs 작업 흐름과 기본 `evidence_k=10`, local sparse embedding을 사용했습니다. 기존 구독 모델을 연결한 custom transport를 사용하며 이 구성을 비교 조건에 포함합니다. 원문은 XML 본문의 텍스트 순서로 전달했고 표와 캡션의 텍스트를 포함했습니다.

## 검색 도구를 연결한 20문항

같은 20문항에서 기본 LLM 답변과 문헌 도구를 사용하는 모듈을 비교했습니다. 기본 LLM은 검색 도구 없이 답했고, 코어 유무의 두 모듈에는 같은 문헌 도구와 최대 3응답·2도구 호출을 허용했습니다.

| 방식 | 계획 문항 | 채점 답안 | 정답 | 채점된 오답·모름 | 미채점 |
|---|---:|---:|---:|---:|---:|
| 같은 LLM만 | 20 | 20 | 13 | 7 | 0 |
| 공통 코어 없음 | 20 | 5 | 5 | 0 | 15 |
| 공통 코어 있음 | 20 | 5 | 5 | 0 | 15 |

코어 없음의 미채점 15건은 응답 상한 안에 최종 답안을 내지 못했습니다. 코어 있음은 같은 사유 14건과 HTTP 오류 1건이었습니다. 이 조건에서는 코어 유무에 따른 정답 수 차이가 관측되지 않았습니다. 원문 제공 15문항과 검색 20문항은 별도 묶음으로 집계합니다.

## 평가 기록

원 저자의 선택지 일치와 기권 정의를 사용했습니다. 정상 반환된 오답·모름, 실행 오류, 호출 전 중단을 각각 보존했습니다. 총 계획 120개 방식·문항 조합 중 117개 실행 기록과 3개 호출 전 중단을 집계했습니다. 독립 문항 수와 방식별 반복 수는 표의 분모에서 구분합니다.

- [전체 집계](aggregate.json): 모든 방식의 계획·완료·정답·실패 수와 조건.
- [전체 CSV](all-arms.csv): 같은 수치를 표로 확인.
- [동일 원문 14대상 자원 표](provided-resource14.csv).

코어 구축 문헌과 시험 문항 출처의 정확한 PMCID 일치는 확인 대상 20개 출처 기록 중 0개였습니다. 제목 또는 간접 개념 중복은 별도로 측정하지 않았습니다. 데이터 파일에는 집계와 원 결과의 검증 해시를 담고 있으며, 시험 문항·정답·원문 파일은 해당 데이터의 제공 경로와 이용 조건에 따라 관리합니다.
