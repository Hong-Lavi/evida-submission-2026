# Review procedure for the frozen chronology component assay

Read `attempt-03/blind-review/Bxx/visible-case.json` and its unchanged `answer.txt`, together with `frozen-source.json`. Do not open `review-key-private.json`, arm-specific requests, or frozen product inputs before freezing judgments. The first two invocation directories contain local setup errors, not model answers. `attempt-03/component-terminal.json` records the actual response coverage when complete.

The reference loop is fixed scientific context, not an adjudicated mechanism. Added timing/history facts are explicitly synthetic. P4/P5 include an immutable earlier prediction record with scenario event sequence; these are not claims that a biomedical experiment occurred on a wall-clock date. Use the six P1–P6 expectations/failures in `fixed-challenges.json` as evaluator-only criteria. D1–D4 are outside this assay.

For each blind answer, preserve an exact response quote/location and record:

- Whether the exact assigned measurement instance is distinguished from background/original observations.
- The answer's declared chronological meaning and whether its stated evidence supports it.
- Whether an asserted prior prediction points to the actual prior fixture record, preserving its wording and pre/post-outcome status.
- Whether timing uncertainty is retained rather than guessed, and whether any unsupported scientific or causal conclusion follows.
- Primary case result: pass only when all expected distinctions hold and none of that case's failure conditions occurs. Otherwise fail, with the specific unmet distinction. A missing/identity-rejected response is unassessable, reported separately with all six planned cases retained for each arm.
- Native structured-output validity separately from scientific correctness. Equivalent prose can pass for the plain arm; field count and formatting do not earn scientific credit.

Freeze this per-answer review before opening the mapping. Then group by arm and case, disclose planned/attempted/returned/assessable counts, list each case result, and report corrected-versus-frozen paired changes. Plain versus product changes both guidance and output structure; product versus product is the narrower chronology edit comparison. With six deliberately chosen development counterexamples and one response per arm/case, no population-level accuracy or statistical superiority claim is supported. Output format can reveal that an answer is plain versus structured, so arm blinding is partial; baseline versus corrected product labels remain concealed.

Original protocol, scientific inputs, common transport task and rubric were frozen before the first invocation. The controlled execution repair changed only invocation permission and location-bound input metadata, with all previous errors preserved. No answer was inspected to adapt a protocol or prompt. The single-response budget supersedes the earlier general plan's four-response ceiling for this assay and is identical across all three arms.
