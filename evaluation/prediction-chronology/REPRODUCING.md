# Exact execution semantics and reproducibility limits

The public verification path is `python verify.py`. It is independent of the original execution driver and reproduces integrity checks and arithmetic over the preserved manual judgments. It does not generate new reviews. `offline-public-result.json` records the public-only run; `offline-with-local-source-result.json` records an additional run with the verified original packet. The latter's source checks cannot be repeated from this distribution alone.

The exact supplied scientific instruction text, request, case, source identity, and response contract are in each `records/attempt-03/component-calls/Bxx/request.json`. Only the source-packet slot is externalized. `transport-semantics.json` contains the exact original `TASK`, common `ENVELOPE` (`{"answer": string}`), and `QUESTION`, extracted without executing the driver. An arm with a non-null `response_contract` must put the matching JSON scientific record inside that answer string; the direct-model arm writes prose. No extra intent, frame, or complete Runner envelope was requested.

The unchanged execution logic is retained in `records/run_component_assay.py`, `records/execute_controlled.py`, and the two setup launchers. They are historical execution sources, not drop-in public entrypoints: they assume a private audit layout and a pinned LAVA checkout. Exported host paths are marked placeholders. Do not run them expecting a source download or an authorized subscription. Product planner/schema sources are preserved under `records/frozen-product-inputs/` so the delivered contracts and chronology-only differences remain inspectable.

Runtime pin: LAVA `e0c05caf01501692f380a16b69eddcdae021549a`; provider adapter `codex-subscription-exec-v3`; observed CLI `codex-cli 0.162.1`; requested and recorded actual model `gpt-6-astra`, effort `max`. The pinned runtime itself and an authenticated subscription are external prerequisites. The exact original source packet is a further prerequisite. No API keys or account configuration are included, and no automatic model invocation is provided.

A fresh comparison using these inputs must preserve the following semantics:

1. Verify the packet hash and restore the original requests with `prepare_requests.py`. The preparation tool refuses an existing output directory and restores the original request byte hashes recorded in the call receipts.
2. Use the unchanged pinned runtime's indexed-input preparation/restoration with every top-level request field required. Regenerate path-bound metadata for the new directory; do not reuse a relocated private index. Pass the exact transport task and envelope. The historical launches used the runtime's parent-session isolation and strict model identity checks.
3. Use the recorded B01–B18 order, one response per case/arm, max effort, 1,800-second timeout, no web/science tools, no correction turn or provider retry, and at most two concurrent requests. The original successful launch waited for its first accepted response before concurrent continuation.
4. Preserve every response and failure, actual model receipt, raw answer, original fixed rubric, and denominators. Seal independent judgments before revealing the mapping. Newly generated responses need their own review and cannot inherit the included scores.

A new provider run need not reproduce identical answer text. The same model name does not guarantee an immutable hosted model implementation. This artifact supports exact supplied-input recovery when the local packet is available, not deterministic model-output reproduction.

The export transform replaces only private filesystem locators outside scientific records and explicitly replaces `/source_packet` with an external-input descriptor. It preserves raw answers, parsed records, visible cases, rubric interpretation, manual judgments, and batch seals byte for byte. It excludes provider directories, huge prepared-input bodies, and the private mapping file; the authorized mapping is in `unblinded-comparison.json`. `export-manifest.json` connects original hashes to public hashes and lists operations. Preserved historical hashes refer to the original bytes, so a sanitized file need not have its historical hash. The verifier checks both chains where the relevant record is exported.

Original setup failures remain in `records/component-calls/` and `records/attempt-02/component-calls/`. Successful responses are only under `records/attempt-03/component-calls/`. The original challenge file also includes unexecuted D1–D4 mediator-control cases; retain them as planned but unexecuted, not missing chronology answers.
