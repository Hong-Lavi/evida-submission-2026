# Recalculation and source scope

Run `python scripts/verify_manifest.py` and `python scripts/verify_arithmetic.py` from this directory. The latter checks all 221 stored pairs, their 219 groups, the 42-pair native subset, original IDs and positive concentrations, exact rational ratios, log10 values, reported directions, the three distinct records for one structure, and 84 native assay-object hashes. It reads existing results; there is no product worker, fitting or retrieval step. Python's standard library is sufficient.

The arithmetic verifier is separately written and imports neither calculation module. Its ratio tolerance is relative/absolute 1e-14; log10 tolerance is absolute 1e-12. Decimal ratio strings are also compared with exact rational values. `receipts/package-arithmetic-verification.json` records the packaged-data check.

`code/v1/reported_activity_comparison.py` is the exact core used for the preserved 221-pair pass. `code/v2/reported_activity_comparison.py` is the exact core used for the 42-pair native run. Their hashes are in `code-provenance.json`. Importing these modules for separate experiments requires `jsonschema` and RDKit; the recorded native versions are Python 3.12.14, jsonschema 4.26.0 and RDKit 2026.3.6. The modules expose explicit argument validation, native Store binding, a single-pair calculation and bundle evaluation. The included integration patch identifies the registered Runner and worker path.

The public data are a deduplicated projection of the selected scientific fields. `measurements.json` retains 442 activities; `assays.json` retains 66 source assay objects; `documents.json` retains 26 document identities and DOIs. The original response pages and product Store are identified by hashes, with response pointers retained for selected objects. Their full bodies and private application environment are not needed for arithmetic checking. Repeating the exact native Store execution additionally requires the original retained responses, their native artifact construction, and the application revision identified in `code-provenance.json`. A current API response may differ from the dated snapshot.

The v1 pass compared enriched assay-condition copies without checking them against the separate assay response. That is the scope of its 221-pair result. Independent review retained this finding and a decimal scaling case where default precision could erase a very small difference. V2 checks the authoritative retained assay object, marks unsupported copies unverified, converts power-of-ten units exactly and admits up to 50 significant digits with 120-digit arithmetic. The native 42-pair run exercises those boundaries. Its decimal strings and authority fields carry this added precision/provenance; the original values, numeric results and unresolved-condition judgments agree with the corresponding v1 rows. The full 221-pair calculation was not rerun with v2.

The native subset was selected by source coverage before ranking comparison. It contains 42 pairs for CHEMBL3112394, assays CHEMBL3117338 and CHEMBL3117337. An optional 27-pair group is outside the native-run denominator. Broader source exploration contained 840 document/structure possibilities, of which 216 met this narrow metadata pairing and contributed 219 groups/221 source-record pairs. The remaining 624 possibilities lacked the required match evidence and do not represent negative activity observations.

Data transformations are limited to field selection, deduplication, source links, condition-authority annotations and the reported ratio/log10 calculations. Commercially derived compound-property calculations and original publication abstracts/full text are outside this dataset projection. An original document's `document_initial_release` describes its entry history; it is not a claim about the API snapshot release.
